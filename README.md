## 二、先看懂拒审信息

审核邮件里最重要的是三块：

| 字段 | 看什么 |
|---|---|
| Guideline | 条款编号，例如 1.2、2.1(b)、4.3(a)、5.1.2 |
| Issue Description | 审核员具体说哪里有问题 |
| Next Steps | Apple 希望你怎么改 |

不要只看条款编号。比如同样是 2.1(b)，可能是内购找不到，也可能是金币用途不清楚，还可能是网络导致购买页打不开。

## 三、高频拒审原因和解决方案

### 1. 5.1.2：隐私追踪 / ATT 弹窗

**常见原因：**

| 问题 | 说明 |
|---|---|
| 接了广告、归因、统计 SDK，但没有 ATT 弹窗 | 审核认为存在追踪行为 |
| App Store Connect 隐私问卷和实际 SDK 不一致 | 声明和实际采集不一致 |
| 弹窗触发太晚或审核员看不到 | 审核无法验证 |
| 用户拒绝追踪后 App 异常 | 核心功能不能依赖授权 |

**处理办法：**

1. 需要追踪就接 ATT，并在追踪前弹出。
2. `NSUserTrackingUsageDescription` 写具体用途。
3. 核对 App Store Connect 隐私问卷。
4. 不追踪就关闭 SDK 追踪能力或移除相关 SDK。
5. 审核备注写清楚弹窗路径，最好附真机录屏。

### 2. 1.1：不当内容 / 内容尺度

**常见触发点：**

| 位置 | 容易出问题的内容 |
|---|---|
| 图标 | 擦边、低俗、强暗示 |
| 商店截图 | 暴露、挑逗、成人化文案 |
| 描述和关键词 | 暧昧、成人、刺激、换装等表达 |
| App 内默认内容 | 封面、视频、聊天内容尺度过大 |
| AI / UGC 示例 | 可能生成或展示不当内容 |

**处理办法：**

1. 先改图标和五图，很多 1.1 不是代码问题。
2. 删除擦边、成人化、刺激性文案。
3. 默认内容用安全、中性、日常素材。
4. AI、聊天、图片、视频类功能要有内容过滤和举报机制。
5. 不要只靠提高年龄分级解决，年龄分级不是万能挡箭牌。

### 3. 4.3(a)：Spam / 相似 App / 马甲包高频问题

这是马甲包开发最容易遇到的条款。

**审核员主要看：**

- 二进制是否相似；
- UI 和功能结构是否相似；
- 图标、截图、描述是否像批量模板；
- 核心概念是否只是换名换皮；
- 是否多个包共用同一套素材和文案；
- 是否多个账号提交类似产品。

**马甲包常见误区：**

| 误区 | 风险 | 更稳的做法 |
|---|---|---|
| 只换包名、Logo、应用名 | 容易被判定重复包装 | 改定位、功能、内容、截图表达 |
| 多个包共用同一套截图模板 | 元数据相似 | 每个包做独立截图和卖点 |
| 描述批量替换关键词 | 文案相似度高 | 按目标用户重新写描述 |
| 内购页完全一样 | 商业结构相似 | 按场景解释权益和价值 |
| 4.3(a) 后只小改再提 | 容易连续拒审 | 做真实差异化，并写清楚差异点 |

**处理办法：**

1. 不要只换皮，要做出产品差异。
2. 至少改清楚：定位、核心功能、默认内容、截图、描述、购买页。
3. 审核备注里列差异点，不要只说“我们不一样”。
4. 附录屏或截图，让审核员看到核心功能路径。

### 4. 2.1(b)：内购或功能找不到

**常见原因：**

| 问题 | 说明 |
|---|---|
| 审核员找不到订阅入口 | 入口太深或隐藏 |
| 金币、会员、点数用途不清楚 | 不知道用户买了什么 |
| IAP 商品加载失败 | 商品状态、网络、Bundle 配置有问题 |
| 没有恢复购买 | 订阅和非消耗型商品常见问题 |
| 审核备注没写路径 | 审核员只能自己找 |

**处理办法：**

1. 审核备注写清楚路径：例如 `首页 -> 头像 -> Pro -> 月订阅`。
2. 需要登录就提供测试账号。
3. 录屏展示从打开 App 到调起系统内购弹窗。
4. 检查 IAP 商品状态、价格、订阅组、审核截图。
5. 购买页写清楚权益、周期、价格、自动续订说明。
6. 添加并测试 Restore Purchases。

### 5. 1.2：用户生成内容 UGC

有聊天、评论、发帖、匿名发布、上传图片、用户资料展示，都要注意 1.2。

**必须准备：**

| 能力 | 说明 |
|---|---|
| 用户协议 | 注册或登录前展示 |
| 举报内容 | 每条内容附近最好能举报 |
| 屏蔽用户 | 聊天、资料页要能拉黑 |
| 内容审核 | 关键词、图片、人工或后台处理 |
| 反馈入口 | 用户能联系官方处理问题 |

**录屏建议：**

1. 首次打开 App；
2. 展示用户协议；
3. 展示举报入口；
4. 展示屏蔽 / 拉黑入口；
5. 展示客服或反馈入口。

### 6. 2.3 / 2.3.3 / 2.3.6：元数据、截图、年龄分级

| 条款 | 常见问题 | 处理办法 |
|---|---|---|
| 2.3 | 描述和实际功能不符 | 删除当前版本没有的功能 |
| 2.3.3 | 截图没展示真实功能 | 用真实页面做截图 |
| 2.3.6 | 年龄分级没如实选择 | UGC、聊天、消息要勾选 |
| 2.3.2 | 付费功能没说明 | 描述或购买页写清楚 |

**重点：**截图不是宣传海报，截图也是审核内容。不要展示 App 里没有的能力。

### 7. 2.1 / 2.1(a)：Bug、崩溃、无法启动

**提审前必须测：**

| 场景 | 检查点 |
|---|---|
| 首次安装 | 能否正常进首页 |
| 弱网 / 断网 | 是否卡死或白屏 |
| iPad | 是否显示不全 |
| 登录流程 | 测试账号是否可用 |
| 购买流程 | 是否能加载商品 |

审核员打不开，就会直接拒。不要只测开发包，要测上传前的真机包。

### 8. 4.0 / 4-design：页面布局问题

**常见问题：**

- iPad 上文字或价格被遮挡；
- 按钮重叠；
- 弹窗超出屏幕；
- 小屏设备关键按钮不可见；
- 购买页价格、周期、权益显示不完整。

**处理办法：**

1. 测 iPhone 小屏、主流 iPhone、iPad。
2. 弹窗内容多就允许滚动。
3. 价格、按钮、协议链接不要固定宽度硬塞。
4. 如果不支持 iPad，检查项目配置和 App Store Connect 设置。

### 9. 5.1.1：权限用途描述不清楚

系统权限文案要具体，不能写空话。

错误示例：

```text
App needs camera access.
```

更好的写法：

```text
需要访问相机，用于拍摄头像或上传你选择的内容。
```

**处理办法：**

1. 检查相机、相册、麦克风、定位等权限描述。
2. 写清楚为什么用、在哪里用。
3. 不用的权限不要申请。

### 10. 其他低频但危险的问题

| 条款 | 问题 | 处理 |
|---|---|---|
| 3.1.1 | 缺少恢复购买 | 补 Restore Purchases |
| 3.0.0 | 价格 / 商品权益不清楚 | 购买页和备注写清楚 |
| 1.5 | 支持链接打不开 | 检查 Support URL、Privacy URL |
| 4.1 | Logo 或品牌疑似抄袭 | 换原创素材或提供授权 |
| 4.2 | 功能太少 | 增加真实核心功能 |
| 5.2.2 / 5.2.3 | 第三方内容侵权 | 删除内容或提供授权 |
| 5.6 | 开发者行为风险 | 不要重复违规提交 |

## 四、重点总结

1. **5.1.2**：隐私、ATT、SDK、隐私问卷必须一致。
2. **1.1**：图标、截图、描述、默认内容不要擦边。
3. **4.3(a)**：马甲包不能只换皮，要做真实差异。
4. **2.1(b)**：内购和核心功能要让审核员找得到。
5. **1.2**：有 UGC 就要有协议、举报、屏蔽、审核机制。
6. **2.3**：截图、描述、年龄分级必须和实际功能一致。
7. **被拒后**：别只说“已修复”，要给路径、账号、录屏。
